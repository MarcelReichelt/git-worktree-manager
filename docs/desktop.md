# Desktop

`yarn desktop` opens the window. It needs a display. App settings chooses the terminal mode for a new terminal: an in-app terminal, a tmux session, or no terminal section. Terminal is the default.

With nothing selected, a centered card lists registered repositories. An empty card says a repository needs to be added.

## Add a repository

**+** opens Add repository.

Location is a text field. Type or paste a path, or use the folder button. A git directory fills Display name from the repository folder. A bare repository uses the git directory's name. Editing the display name keeps your text when the path changes.

A path that is not a git repository shows that error under Location and disables Add repository. An empty location reports `Choose a repository folder` when Add repository is clicked. An empty display name reports `Enter a display name`. Adding a path that is already registered updates the display name.

## Workspace

The top bar shows the app mark, then one repository tab for each open repository, then +. A repository tab shows the display name and has no close icon. Right-click a repository tab for Repository settings and Close. Repository settings from that menu belong to the clicked repository and leave the selected workspace as it is. Close ends that repository's terminals immediately. Closing the last repository tab returns to the start screen and forgets the set, so the next launch shows the start screen. Quitting remembers the open repository tabs and which one was selected. The next launch opens them in that order and shows each repository's current display name. The selected branch and the terminals are not restored. A path that is no longer registered, or a repository that cannot be opened, is skipped. When the selected one is skipped, the next remaining repository tab is selected, otherwise the previous one. When none remain, the start screen is shown. A long name is cut off, and hovering the tab shows the full display name. A repository tab uses that repository's sidebar color and sidebar text, and the selected tab has a frame in the sidebar text color. The window bar uses the selected workspace's sidebar color and sidebar text. The tabs and + scroll together when they do not fit, and selecting a tab scrolls it into view. A newly opened repository is added at the end and becomes the selected tab. There is one tab for each open repository. + opens the card over the workspace. That card lists registered repositories that do not already have a repository tab, in registry order. Repository settings sits on the right of the Worktrees row and belongs to the selected repository tab. It shows the location, the display name, the worktree mode, the sidebar color, the sidebar text, and the remotes. Changing the display name updates that repository tab immediately. An empty display name reports `Enter a display name` and leaves the stored name in place. Copying the location stays there. App settings sits with minimize, maximize, and close on the right. Drag the top bar to move the window.

## Worktrees

The sidebar heading is Worktrees. Each row is a branch `git worktree list` has checked out. The default branch is first when it has a checkout. A branch with no checkout is absent. Opening a registered repository for the first time this launch prunes remote-tracking refs whose remote branch is gone and asks the remote which branch is its default. Switching to a repository tab that is already open does not. It shows the branch list, the selected branch, and the terminals kept for that repository. The remote is `origin` when it exists, and otherwise the first remote. That answer is stored in the remote's HEAD ref. An unreachable remote keeps the HEAD ref already stored. Creating a worktree, removing one, and the branch actions list without pruning or asking.

Choosing a registered repository from the start screen replaces the card with `Opening` and that display name, then shows that repository tab. Until the worktree list is read, the sidebar and the content show skeletons. Switching to a repository tab that is already open shows the kept branch list at once, then reads again. That card lists every registered repository, because none has a repository tab yet. Choosing another registered repository from an open workspace leaves that workspace in place, without `Opening`, and shows the chosen repository when the open succeeds. A failed open shows the error on the current workspace and leaves that workspace in place. Each repository opened in this launch keeps its selected branch and its running terminals until that repository tab is closed. Clicking the repository tab of the repository that is already open leaves the workspace as it is. The arrangement stays the same across repository tabs. The create dialog opens immediately and shows `Loading branches` until its names are ready. Confirming it shows `Creating worktree` until the new row is in the list. Remove, Update from master, Merge into master, and Push keep the row, keep its branch name, and replace the counts with that action until the list is up to date. Merge does this after Confirm, and the dialog stays up until then. Opening a worktree shows `Loading` and the branch name across the content until its changes and commits are ready. The terminal section shows the tabs that worktree already has, and a new terminal starts with that load. When the terminal section is maximized, that loading text is on the row.

The color beside the name is the status. Hovering it shows the title:

| Title | When |
| --- | --- |
| Local only | No upstream is configured |
| Local and remote | The configured upstream ref exists |
| Remote deleted | An upstream is configured and that ref is gone |

A row also shows the changed-file count, and how many commits the branch is ahead and behind. Those counts use the upstream when it exists, and the default branch otherwise. While a repository tab is open, a read refreshes those counts for the default branch and the selected worktree. Choosing a worktree refreshes that row. Update from master, Merge into master, Push, and creating a worktree refresh the row they act on. Any other worktree keeps the counts it last showed. A worktree that has not been refreshed shows zero. The default branch stays first. After that, a worktree's place follows the later of its newest commit and the changed-file time from its last refresh. A terminal count appears while terminals for that worktree are running, and it is hidden at zero. The count is the number of running terminals, so a tab with two terminals side by side counts as two. It is refreshed with the worktree list and while the terminal poll runs.

Click a row to open it. Right-click a row to open the branch actions: Update from master, Merge into master, and Remove worktree. Right-click that row again to close them. The default branch omits those actions. The primary checkout omits Remove worktree. A right-click on the default branch does nothing, unless that branch is local-only. A local-only branch also offers Push, and that is the default branch's only action. Push publishes that branch and sets the upstream. The remote is `origin` when it exists, and otherwise the first remote. When the repository has no remote, Push reports `No remote to push to`. Update from master merges `master` into that checkout. Merge into master opens a dialog with a Squash checkbox, and the primary checkout has to be on `master`. Remove worktree opens a dialog. Keep branch deletes the extra checkout and leaves the local branch. Delete local branch deletes that checkout and the local branch, even when it is not merged. When the checkout has changes, that delete stops and the button becomes Force delete branch. That second step removes the checkout with those changes and deletes the local branch. A remote branch stays. Cancel leaves both. Pre-remove hooks run before the checkout is deleted. Post-remove hooks run after. The primary checkout stays.

## Create a worktree

Create worktree opens a dialog. The name field is New branch. Existing branches lists names that have no checkout, including a branch that exists only on a remote, and omits a branch whose remote copy was deleted. The heading is absent when that list is empty. Choosing a row fills the name field.

The dialog shows the layout create will use, such as `Workspaces, the app default` or `Sibling, set by this repository`. Confirm runs the same create as the CLI. A new name creates a local branch at the primary checkout's current commit, with no upstream. A local branch is checked out as it is. A remote-only branch is fetched first. Pre-create hooks run before the worktree is added. Post-create hooks run after checkout. See [Worktrees and layouts](worktrees-and-layouts.md).

## Content

The heading is the branch name. Click it to copy the name. IDE sits beside the name. It stays disabled until App settings has an IDE command. The command runs in the selected checkout. `{folder}` is replaced with that checkout path, quoted for the shell. A command without `{folder}` is left as it is and still runs with that checkout as its working directory. An empty checkout reports `No checkout for this branch`. A command that fails shows that error on the workspace.

Under the branch name, the changed-file count shows as soon as the worktree opens. The commit count appears once the total for that list is known, and loading further pages does not change it. When the total cannot be read, the commit count stays absent.

The default branch is the name stored in the remote's HEAD ref when that branch exists locally. The remote is `origin` when it exists, and otherwise the first remote. When that branch does not exist locally, or no HEAD ref is stored, the default branch is `master` or `main` when only one of those local branches exists. When both exist, it is whichever of them is checked out on the primary checkout, and `master` when the checkout is neither. When neither exists, it is the branch checked out on the primary checkout.

Changes lists files in that checkout, with lines added and deleted. Click a file to show its diff.

On the default branch, Commits is that branch's history, 30 commits at a time, and scrolling the list loads the next page. The heading total is that same history. On any other branch, the list and the heading total are the commits that are not on the default branch, 30 at a time, and scrolling the list loads the next page. Click a commit to show the files it changed and the diff for the selected file.

The diff is inline. Each line shows the old line number and the new line number. A removed line is red and has only the old number. An added line is green and has only the new number. Context, the unchanged lines kept beside a change, has both numbers and is not given a change color. The changed span inside a line is marked more strongly than the rest of that line. A change that is only whitespace is colored. The language of the file is not colored. Three lines of context stay around each change. The stretches between those changes are not shown. Lines do not wrap. The line numbers stay at the left while the line text scrolls sideways. Only the lines in view are drawn.

A rename shows `Renamed from …` above the lines. A binary file shows `Binary file`. A file with no line changes and no rename shows `No diff for this file`. A new file is entirely green. A deleted file is entirely red.

In the folded diff, each hidden stretch of unchanged lines is a fold. The fold shows `1 hidden line` or `N hidden lines`, and the buttons `3 more lines` and `All lines`. `3 more lines` reveals up to three lines at each edge of that fold, directly beside the context already shown, and the count updates. A fold of six or fewer hidden lines opens completely. A fold at the start or the end of the file has one edge and reveals three lines there. `All lines` opens the whole stretch. The same file keeps the folds that were opened. Another file starts folded. A reload after the file changes starts folded. The next launch starts folded. `All lines` on a stretch of more than 100,000 lines shows `This file is too large to show` on that fold, that fold stays closed, and the rest of the diff stays. `3 more lines`, and `All lines` on a smaller stretch, still open those lines.

Full file shows every line of that diff. The lines stay colored the same way, and there are no folds. The switch offers Folded and Full file and starts on Folded. The choice is for the whole app: it applies to the next file and to the next launch. Previous change and Next change jump to the previous or next change. They sit on the diff in Full file, and a change at the end of the file leaves Next change disabled. A side over 2 MiB or 100,000 lines shows only `This file is too large to show`, and the saved mode stays Full file until Folded is chosen. The switch stays visible when the diff shows only a sentence.

Side by side shows the old file on the left and the new file on the right. Corresponding lines share a row and one scroll position. A context line is on both sides. A run of removed lines pairs in order with the following added lines. A leftover removed line has an empty cell on the right, and a leftover added line has an empty cell on the left. An empty cell has no line number and no change color. A fold is one row across both columns, and its `3 more lines` and `All lines` buttons change both columns. A new file is empty on the left and green on the right. A deleted file is red on the left and empty on the right. Full file side by side shows the complete old file on the left and the complete new file on the right, and only the rows in view are drawn. The switch offers Inline and Side by side and starts on Inline. Drag the divider between the two sides to resize them. The sides stay within the pane, so the divider stays where you can reach it. A long line scrolls from a swipe over the diff or from the bar under both sides, and both sides move together. The line number stays put. Double-click that divider to make the sides equal. Neither side shrinks below 80px. The share is saved for the whole app, and the next launch restores it. The choice of Inline or Side by side is for the whole app: it applies to every repository, the next file, and the next launch. The size limits for All lines and for Full file apply to both columns. The switch stays visible when the diff shows only a sentence. Lines do not wrap, and the line number in each cell stays put while that cell's text scrolls sideways.

In Changes, the old side is the commit HEAD points at, and the new side is the checkout as it is, including changes already added for the next commit. For a commit, the old side is that commit's first parent and the new side is the commit.

Drag the splitters between the panes to resize them. Each region scrolls on its own.

Changes and Commits keep their share of the stack. Dragging the terminal section, resizing the window, or collapsing and expanding that section applies the share again. When the stack can hold both headings, each one keeps at least 44px. A shorter stack is split by the share, and the terminal section can still grow. Double-click the divider between Changes and Commits to split the stack in half.

Double-click the divider between the stack and the diff to give those two columns equal width. With a commit's files open, double-click either vertical divider to give the stack, the commit files, and the diff equal width.

The arrangement is saved for the whole app: that share, the Changes column width, and the commit-files column width. Switching repository tabs keeps it. Reopening the app restores it. With nothing saved, Changes starts at 280px and each column starts at 240px. A saved terminal height that hides a heading shrinks in the window so both headings stay visible when the window can hold them. When the window is tall enough again, that saved height comes back. The column widths stay as saved. The shrunk height is not written back.

## Terminal

The terminal is a row at the bottom of the worktree, under the changes, the commits, and the diff. While a repository tab is open, each worktree remembers whether its terminal section is collapsed, docked, or maximized. Switching worktrees shows that worktree's state. Switching repository tabs shows the selected worktree of that tab. A worktree that has not been opened starts collapsed, and the next launch starts every terminal section collapsed. Terminals are not restored. Drag the horizontal splitter to resize the docked height. That height is the app-wide arrangement, shared by every worktree, and it is restored on the next launch. Double-click that splitter to set the docked height to one third of the area under the branch heading. Resizing the window later leaves that height in place. The chevron collapses that worktree's row to the header and hides the splitter. Expanding restores the docked height. Collapsing and maximizing belong to the worktree for the life of the repository tab. They are not saved. While the row is collapsed, the header shows how many terminals are running for the selected worktree when that count is greater than zero. Killing the last terminal collapses that worktree's row, including when it was maximized, and the content is visible again. Other worktrees keep their state. Collapsing leaves running terminals alive. Expanding an empty terminal section starts one terminal.

Selecting a worktree does not start a terminal. The terminal section shows that worktree's state, and a worktree with no terminal is collapsed. A shell that is already running keeps running, and a tmux session that is already running for that worktree stays. Expanding an empty section starts one terminal. Expanding shows a terminal that is already there and does not start another. A worktree keeps its tabs while another worktree is selected, and while the row is collapsed.

The terminals for a worktree sit in numbered tabs in the header. A tab holds one terminal, or two side by side. The number is the tab's position, starting at 1. Closing a tab renumbers the tabs after it. Inserting a tab renumbers the tabs after the insertion, so a new tab between 1 and 2 becomes 2 and the old 2 becomes 3.

A play button sits immediately to the left of Split when the selected checkout resolves a preset. It is in the workspace and in Terminals. It opens the preset list, including when there is only one preset. Choosing an entry appends that preset's tabs and does not also open an empty terminal. Selecting a worktree does not run a preset. See [Presets](presets.md).

New, Split, and Kill are icon buttons on the header. New adds a tab at the end with one terminal. On a collapsed or empty section, New also expands the row and starts one terminal. Split adds a second terminal to the current tab. The two panes sit side by side with a splitter between them. Double-click that splitter to give the panes equal width. Dragging it, and that double-click, are not saved. Split is disabled when the current tab already has two. Kill on the header kills the focused terminal. Killing a terminal closes it. The last terminal in a tab closes the tab.

Maximize is an icon button immediately to the left of Kill. It stays visible while the row is collapsed. Maximize covers the branch heading, Changes, Commits, and the diff, and the branch list stays. The terminal row fills the content sheet. The docked height is kept. Maximize lasts for this worktree while the repository tab is open. It is not saved, and there is no keyboard shortcut. The button again restores the docked height. The chevron while maximized collapses the row, and the next expand restores that docked height rather than maximize. Maximize while the row is collapsed covers the content directly. The next launch starts the terminal section collapsed and restores the docked height.

Each tab has its own Kill button at the end of the label. It is shown while the pointer is over that tab, while the tab is focused, and while that tab's name field is open. It stays in the header while the row is collapsed. It kills every terminal in the tab, including when that tab is not the focused tab. A tab that was not focused stays focused. Killing the focused tab focuses the tab that moves into its place. Killing the last tab collapses the row. A long label ellipsizes, and this Kill button stays at the end of the label.

A tab with two terminals shows a Kill button at the right of each pane header. It is shown while the pointer is over that header and while that terminal's name field is open. It kills that terminal. The other terminal stays. A tab with one terminal has no pane header, so it has no pane Kill button.

With no custom name, a one-terminal tab shows its number and the foreground process name, such as `1 bash`. A split tab shows both names, such as `1 bash · npm`, and each pane shows its own name. An empty name still keeps its place. The process name is the running command, and the shell name again when that command exits. A tooltip on a terminal says `tmux session` or `in-app terminal`.

A one-terminal tab is one target. Right-click it for Rename, Kill, and Split. On a split tab with no custom name, each name is its own target, in pane order. Hovering a name outlines that name. Left-clicking a name focuses that tab, if it was not already, and moves the caret into that terminal. Right-clicking a name opens that terminal's menu: Rename, Kill, Split, and Unsplit, with Split disabled. Left-clicking the number, the middle dot, or the rest of the label focuses the tab and leaves the focused terminal as it was. Right-clicking those opens the tab menu: Rename and Kill of the whole tab. Kill on a tab kills every terminal in it. A custom name replaces the names in the label, and that whole label is the tab. Right-click a pane header for that terminal's menu. Unsplit moves the right-clicked terminal into a new tab immediately after the current tab and focuses that new tab. The other terminal stays. Right-clicking a Kill button opens the menu of the tab or terminal that button kills. A right-click does not move focus.

Rename turns the name into a field, and the Kill button for that tab or pane stays beside the field. Enter commits the name. An empty name clears it, and the process name comes back. Escape closes the field without renaming, and Escape closes the menu without renaming. Right-clicking the Kill button while the field is open drops the uncommitted name and opens the menu. Splitting a renamed one-terminal tab keeps that name on the existing terminal. The new terminal starts from its process name. Renaming a split tab replaces the label until the name is cleared. The pane headers still show each terminal's name. Renaming a terminal inside a split tab sets that terminal's name until it is cleared. Unsplit keeps a renamed terminal's name on its new tab. When one terminal of a pair is closed, a custom tab name stays and the remaining terminal's name is dropped. Without a custom tab name, the remaining terminal's name becomes the tab name.

App settings chooses the terminal mode: None, Terminal, or Tmux. Terminal is the default, including when tmux is installed. None removes the terminal section, so there is no row, chevron, or New, and selecting a worktree starts nothing. Terminal starts an in-app terminal. Tmux starts a tmux session. New and Split create a terminal of the selected mode.

The Terminal option has an edit button for the shell command. The shell command is one program path, with no arguments, stored in app settings. A blank shell command starts the login shell, then `/bin/bash`, then `powershell.exe` on Windows, using the first one that can start. The login shell is `SHELL` when that is a non-empty path, and otherwise the OS user shell. The shell starts interactive, so its own config loads. A path that fails to start shows the workspace error. Changing the shell command leaves terminals that are already running, and terminals started afterward use the new command. Tmux mode ignores the shell command.

The Tmux option is disabled when tmux is not on PATH. Its tooltip is "tmux is not installed". Windows does not hide that option when tmux is installed. If the saved mode is Tmux and tmux is missing, the app behaves as Terminal mode and does not rewrite the saved setting.

Changing mode asks only when the mode you are leaving still has a running terminal of that mode. None has no terminals of its own, so leaving None does not ask. A switch with nothing running does not ask. The dialog offers Keep, Kill, and Cancel. Cancel leaves the mode and the terminals unchanged. Keep leaves those terminals running and shows them on the same tab strip as the mode you are entering. A split tab can hold one in-app terminal and one tmux session when the mode changes between the two panes. Kill stops every terminal of the mode you are leaving, and only that mode. Leaving Terminal kills in-app terminals. Leaving Tmux kills the app's tmux sessions, including sessions for repositories that are not open, and leaves tmux sessions that are not the app's. If the selected worktree then has no terminals, the section collapses. Expanding an empty section starts one terminal of the new mode. New starts one terminal of the new mode. If any terminals remain, the section stays as it was, expanded or collapsed, and shows them.

Switching to None hides the section. Keep leaves the terminals running, and they show again when you leave None and select that worktree. Switching repository keeps the selected branch and the running terminals of each repository opened this launch. In-app terminals keep running while another repository is selected, and they are not shown on that repository. Tmux sessions stay with the repository that owns them. They stay off this workspace's tab strip and appear when that repository is open again. While the mode is Terminal, tmux sessions for the open repository still appear on the tab strip. They stay hidden while the mode is None.

In Tmux mode, the session name starts with `gm_`, a short hash of the repository path, and the branch. A branch of letters, digits, and hyphens is used as itself. A slash in the branch stays in the session name. A character tmux cannot keep is encoded, and a short hash of the branch is added when that encoding would otherwise be a tmux-safe name. That name is the tmux session, not the tab label. `tmux list-sessions` shows the same sessions, and `tmux attach` opens one outside the window.

Opening a repository looks for this app's tmux sessions that were created before a session recorded its branch. Those sessions have no recorded branch. The old name replaced every character outside letters, digits, and hyphens with a hyphen, so `feature/foo` and `feature-foo` both produced a name containing `feature-foo`. When that old name matches one current branch, the app records that branch on the session and does not ask. The session keeps its old name and keeps running. A branch created later that would use the same old name does not list that session. When the old name matches more than one current branch, the app asks before keeping the session. The question lists each of those sessions for the repository being opened. For each one it offers the matching branches, Kill, and leaving the session unchanged. Choosing a branch records that branch, keeps the old name, leaves the session running, and lists it only for that branch. The session is not renamed onto the newer prefix. Kill ends that session, so the other matching branch does not list it. Leaving a session unchanged does not record a branch and does not kill it. The workspace still opens, and opening that repository again asks again. Escape, or a click on the backdrop, leaves every remaining session unchanged. A session whose old name matches no current branch is left running, and the app does not ask about it. A tmux session that is not this app's stays running and does not appear in the question. Sessions for a repository that is not being opened are left until that repository is opened.

App settings chooses the terminal font and the terminal background and foreground. The font family is `UbuntuMono Nerd Font Mono` by default, and the terminal uses that name followed by `monospace`. The background starts at `#1e1e1e` and the foreground at `#d4d4d4`. A terminal that is already open uses a new font or color immediately. The header stays `#252526`.

App settings also chooses the default layout, Workspaces or Sibling. Create uses that layout when the repository config sets no mode. The IDE command is a field in the same dialog. Colors cover the sidebar, the sidebar text, the content sheet, and the terminal background and foreground. The sidebar, the content, and the terminal rows offer swatches and a custom color. Sidebar text is white or black, and it starts white. The sidebar starts at `#1a3c2b` and the content at `#f7f7f5`. Reset restores those colors and white sidebar text. The font and the IDE command stay as they are.

## Worktree mode

Repository settings lists Worktree mode under the location. The line under the heading names the layout create will use, and whether the repository config or the app default set it. Workspaces and Sibling write `[layout].mode` in `.git-worktree-manager/config.toml`. Choosing one writes that mode and leaves the rest of the file in place. An unsupported mode shows its value, with neither choice selected, until Workspaces or Sibling replaces it. When the open repository has no path on disk, the radios stay on the app default and write no config.

## Remotes

Repository settings lists each remote under Remotes. The name is a label. The URL is the fetch URL, and it is read-only. Hovering or focusing a row shows the edit icon.

Add remote opens a dialog for the name and URL. That URL is used for fetch and push. Edit remote changes the name and the fetch URL, or removes the remote. A push URL that already differs from the fetch URL is left as it is. A failed change is rolled back to the previous name and URLs.

## Dismiss

Escape closes one layer. An old tmux session question closes first, then the terminal-mode question, then App settings. Add repository closes before Repository settings. Add remote and Edit remote close before Repository settings. Merge into master and Create worktree close before the repository card. A repository tab menu closes before the repository card. A click outside that menu closes it. A rename field and a terminal menu close before the branch menu. A click on a dialog's backdrop closes that dialog. A click or right-click outside the branch menu closes the menu. Close on the repository card closes the card. A click on the card's backdrop closes it too.
